Weasis 5 is a new line of the viewer: a new plugin platform, a command interface shared by scripts, integrations and AI agents, and hanging protocols that open any study ready to read.
This first preview is for the invited expert panels, plugin developers and testers.
It is **not for clinical use**: it has not been validated, it may lose a display or refuse an action, and some features are incomplete.
The 4.8.0 release stays the viewer for daily work.

## What this preview is

- **Who it is for.** Radiologists, cardiologists, pathologists and technologists who agreed to validate a feature with their own studies; PACS administrators who integrate Weasis; plugin and integration developers; translators.
- **What it is not.** A release. The vocabulary of the commands, the extension points and the file formats of the new documents may still change before 5.0.0; every change will be listed in the notes of the next beta.
- **How it coexists with 4.x.** The preview installs beside Weasis 4.x and never touches it: it keeps its own settings, cache and data folders (the per-OS application folders, not `~/.weasis`), it does not import the 4.x settings and nodes (a manual import comes in a later beta), and it does not register the `weasis://` links, which keep opening the installed release.
  The window title and the About box say *preview, not for clinical use*, and a notice says it once at the first start.
- **How to remove it.** Uninstall *Weasis 5.0.0* with the tools of the operating system (Apps on Windows, the `.pkg` receipt on macOS, `apt` or `dnf` on Linux); the settings folder of the preview can be deleted by hand, 4.x is not affected.
- **System requirements.** A 64-bit Windows 10 or later, a macOS supported by the bundled Java 27 runtime (Intel and Apple silicon), a Linux with glibc 2.27 or later (Ubuntu 18.04, Debian 10, RHEL 8 and later); an older Linux is told so at start and stops.

## What is new since 4.8.0

**Hanging protocols.**
A study of any imaging type opens ready to read: the protocol engine matches the series on what they are (orientation, kernel, contrast phase, weighting, laterality, priors), not on their position in the study, with a built-in library per modality and subspecialty.
*Keep this display* saves the exact reading state of a study and restores it next time; *Save as protocol* turns the current display into a protocol applied to similar studies.
The *why* panel explains every cell, names the header, the table or the heuristic each decision came from, and takes a correction that the engine remembers.
Priors and mammography mirroring, sessions, the protocol bar to step through a protocol, the DICOM hanging protocol exchange and the `hp:` commands are part of it.

**Windows, screens and the workspace.**
The docking engine is written for Weasis: tabs drag between groups, split the workspace or detach into their own window; a window per screen with a role (diagnostic, navigation), tools as views that keep their place, a shell of fixed slots around the workspace, snapshots that restore every window (#953).
Keyboard shortcuts and the `workspace:` commands drive all of it.

**The DICOM explorer.**
Modes by context (a reading list, a patient, a study), smart filters on what the series are, objects (reports, segmentations, structure sets, waveforms) as items of the study, study hints when a protocol or a kept display applies, the `explorer:` commands.
Parts of the redesign (#947) come in a later beta.

**Measurement tools and profiles.**
A registry of graphic tools with stable keys, the classic tools that were missing, tool profiles per modality and practice, the calibration of every spatial measurement reported with its source.

**Identity masking, device masks and redaction.**
The masking of 4.8.0 continues: values that cannot be shifted are hidden, a library of redaction regions keyed on the acquisition device, a masking editor, a warning in every dialog that produces an image when text may be printed in the pixels, and a pixel review that scripts and agents must obtain before they capture (#957).

**Printing.**
One page model in millimeters and one renderer for the preview, the system printer and DICOM print, so a 2 × 3 layout prints at the resolution of the device (#509); `print:` commands.

**Subtraction.**
Post-contrast minus pre-contrast as a derived series that hangs, projects and reformats like any series; phases of a dynamic series and their MIP; DSA mask subtraction with pixel shift and the motion correction (both experimental); `subtraction:` commands.

**3D, zoom and color.**
The volume renderer calls OpenGL directly through the Java Foreign Function & Memory API, so Weasis ships no OpenGL library of its own and the crashes of closed 3D views are gone (#954); one volume per series is built once and shared by MPR, rendering, fusion and the derived series; zoom happens at the pointer (#557); the display is color-managed with the ICC profile chosen for the screen on the Monitors page.

**Waveforms and whole slide images.**
An ECG viewer with the 12-lead and Cabrera layouts, calipers with QTc, filters, comparison with a previous ECG, export, and T.261 compressed waveforms read transparently (#413).
A whole slide imaging viewer for DICOM slides from local files: navigation at every magnification, minimap, scale bar and the measurement tools with the Pathology profile; frame streaming from DICOMweb comes in a later beta.

**Settings.**
One model for every setting and document: a catalog with built-in, site and user layers, a settings package that a site exports and imports, machine and secret stores; the window/level presets, the color maps and the hanging protocols are documents of the same kind.
Weasis 5 uses the application folders of each operating system (#409).

**The platform.**
The OSGi framework is replaced by pf4j plugins (#951); the common libraries are on the class path and a per-user AOT cache shortens the start on Windows and Linux (#952); the plugin manager loads the plugins of the package, of the site and of the user under a site policy with signatures and trust tiers; the integrity of the served plugin set is checked against a signed list; an audit trail plugin sends PS3.15 messages by syslog; TLS as a DICOM client with `dicom:echo`.

**Commands, scripts and agents.**
`weasis-cli`, installed next to Weasis, sends a `namespace:verb` command to the running instance and prints a JSON answer (#955); `help` navigates the twenty namespaces and `help --agent` prints the instructions an AI agent needs; a script runs a list of commands with `@expect` checks and a JUnit report (#956); every event of the viewer is on one bus that a client can stream; checkpoints and rollback around a script or a remote batch, undo of drawings, *Restore the display* after an agent's batch; a remote caller gets only what the restriction policy opens.

## What to test

One scenario per feature; the expected result is in the scenario sheet that comes with the invitation.
Use your own studies, with the masking on when you share a capture.

| Feature | Scenario |
| --- | --- |
| Hanging protocols | Open a CT, an MR and a mammography with a prior without any viewer open: does each cell hold the series you would have chosen? Correct one cell from the *why* panel, keep the display, close and reopen the study. Save the current display as a protocol and open a similar study. |
| Windows and screens | On your reading station, open a study on every screen, detach a tab into a window, save a snapshot, restart and restore it. |
| Explorer | Load a folder of studies and a query from your archive; find a series by what it is; open a report and a segmentation from the study. |
| Measurements | Measure a lesion, an angle and a region on CT and ultrasound; check the values and the units against your usual tool. |
| Masking | Open a study with burned-in text on an ultrasound; check the warning of the screenshot, print and export dialogs; export a redacted copy. |
| Printing | Print a 2 × 3 layout on your printer and to your DICOM printer; compare with 4.8.0. |
| Subtraction | Open a dynamic MR or a DSA run; build the subtraction and the MIP of the phases; send the derived series to your archive. |
| 3D and zoom | Render a CT volume, close and reopen the view several times; zoom with the wheel on a detail. |
| ECG | Open 12-lead ECGs from your devices in the 12-lead and Cabrera layouts; measure QT and compare the QTc with your reference system; compare with a previous ECG. |
| Whole slide images | Open a DICOM slide from a file; navigate at every magnification; measure with the Pathology profile. |
| Settings and sites | Export a settings package from one workstation and import it on another; set a site layer. |
| Commands | Run `weasis-cli help`, then a script of the repository (`tests/smoke/`) against your instance; drive a demo from a terminal. |

The scripted smoke suite of the repository (`tests/smoke/*.weasis`, run by `SmokeSuiteTest`) is the suite each candidate passes before upload; the examples of the Agent Skill ship with the installer under `lib/app/skills/weasis`.

**How to send a report.** Open an issue with the template of the feature (label `5.0-preview`): the scenario, the operating system and monitors, what you expected, what you saw, a masked screenshot or a capture by `view2d:capture`; opinions and questions go to the *5.0 preview* category of the Discussions.
The guided session and the questionnaire are arranged with your invitation.

## Known problems

- Windows and macOS: printing, the ICC display measurements and the scripted suite were run on Linux only; a short manual list covers them on the other platforms.
- The 4.x settings, nodes and presets are not imported; configure the preview by hand or with a settings package (the *Import 4.x settings* action comes in a later beta).
- The remote mirror of the hanging protocols against a Viewer Hub, the selective download and the synchronization across studies with different frames of reference are not covered by this beta.
- The UPS-RS AI workflow is not in this beta.
- Whole slide images stream from local files only; DICOMweb frame streaming and OpenSlide come later.
- The T.261 transfer syntax UIDs are placeholders until Supplement 253 is final; the beta reads them from the dictionary or the system property.
- The plugin manager has no *verified* tier and no registry yet; a plugin of a site runs under the site policy.
- The AOT cache is off on macOS, so the start is slower there.
- With two separate X screens (no Xinerama or RandR), a viewer window may open on the wrong screen.
- The `workspace:list` answer of the ultrasound viewer reports panes that carry no image.
- The interface is only partly translated: strings unchanged since 4.8 are translated, new and renamed ones are in English, and a few messages may show a raw `%s` placeholder (see *For translators*).

## For developers

- The developer kit is in the repository: `docs/README.md` (module map, build and run, the concept pages), `docs/plugins.md` (writing a plugin, loading it, packaging and signing, what changed from 4.x), `docs/testing-with-commands.md`.
- Breaking changes from 4.x: no OSGi API, no Jackson from the platform, preferences scoped by plugin id, configuration keys renamed (#951), `base.minimal.version` 5.0.0, one class loader per plugin.
- The command API of this beta is **2.30**; a verb or an option is never removed within the 2.x major, a renamed one keeps its old spelling as a hidden alias; `weasis:info` and `help --json` report the version.
- The plugin archetypes (`archetype/`) generate a plugin with a tool, a toolbar and a command namespace with its test; a development build accepts an unsigned plugin through `plugins:add`.
- What may still change before 5.0.0: the command vocabulary, the list of extension points, the plugin signature and manifest formats, the `Provenance` record and the result schemas.
  Build against each beta; the notes of the next one list what moved.
- Questions go to the *Plugins for Weasis 5* thread of the Discussions.

## For translators

- There is nothing to translate for Weasis 5 yet: the `weasis-5` Transifex project opens once the interface is stable, so that you only translate strings that will not move again.
  Until then, keep working on the `weasis` project (Weasis 4.8).
- This beta shows the translations of the `weasis` project: a string unchanged since 4.8 appears translated, a new or renamed one appears in English.
- The source strings of 5.0 are already cleaned up (one key, one meaning; one placeholder style, `{0}`; shared strings in `common`; a developer note on every key, with the character limit where the slot cannot grow).
- When `weasis-5` opens, it is built from the `weasis` project (languages, teams, translation memory and glossary preserved), so every translation of an unchanged string carries over; it comes with a glossary of the new vocabulary and screenshots of the dialogs and pages.
